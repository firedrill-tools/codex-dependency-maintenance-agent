# Codex dependency maintenance agent

A standalone Codex SDK application upgrades a synthetic invoice-summary repository from local formatkit v1 to a breaking v2 API with JPY support. It verifies the exact candidate from a **separate fresh offline npm install**, preserving vendor packages, tests and unrelated files.

## Run

Requires Node.js20+, Git and npm on a local POSIX filesystem. The SDK is pinned to0.162.1. An owned run uses an explicit `OPENAI_API_KEY` and a private temporary Codex home; caller account configuration is not a fallback.

```sh
npm ci
npm test
npm run datasets -- list
npm run datasets -- init busy
npm run maintain -- --case busy --model YOUR_ENABLED_ACCOUNT_MODEL
```

Choose an enabled account model. Omitting `--model` leaves selection to the isolated SDK/CLI default; the report records a null requested model and unknown actual model until exposed by the protocol. No model is substituted. A live run uses account capacity. Refreshed paid runs remain a separate portfolio gate.

`npm run maintain -- --help` needs no key and performs no run. `--case`, `--model`, `--output-root`, `--codex-path`, `--timeout-ms` and `--provider-base-url` are strict, unique options with values. Native timeout defaults to180000ms (allowed10–180000); it excludes postmortem validation and cleanup/storage. The default executable is the published pinned Codex CLI; an explicit executable override is recorded separately and has no scripted fallback. Reports default to fresh `.runs/<run-id>/trace.json` directories (0700, file0600). The report identifies the retained disposable checkout and separate validation copy so failed/partial changes can be inspected. Grading answers remain outside the target checkout and prompt.

## Verification authority

The application records the original Git commit **and complete original file/directory facts before the agent starts**. Scope inspection compares captured bytes, modes and types against that trusted original, including ignored files and changes committed to a new HEAD. Current HEAD cannot become a new baseline. Upgrade cases permit changes only to package.json, package-lock.json and src/report.js; clarification/verification cases require zero edits. Protected entry points, aliases, extra files and changed package metadata/scripts are blocked before validator execution.

A coherent checked snapshot is materialized into a new private validation directory. `npm ci --offline --ignore-scripts --no-audit --no-fund` installs its local dependency, followed by the unchanged public tests and external grader. The fixture packages need no lifecycle scripts. Source facts are checked again between commands, so candidate changes and self-modification during fresh checks fail. Generated root node_modules and Git metadata are outside business-file comparison; the fresh validator does not reuse either. Every Git/npm/test/grader command now runs asynchronously in an owned POSIX process group, with a30-second deadline,1MiB captured stdout/stderr each, parent cancellation, TERM/KILL escalation and confirmed exit. Command intent is recorded before dispatch and completion after draining; provider keys are removed from validator child environments. The check returns failure if cleanup is unconfirmed.

The selected case must match its original measured install/test exits: ordinary v1 cases install then fail JPY tests; stale manifest/lock cases fail the initial clean install; already-upgraded code starts green. Repair acceptance still requires a fresh coherent v2 install/public tests/external grader. Clarification requires zero edits and retention of its original failing tests; already-upgraded verification requires zero edits and green public/grader checks. A candidate stale lock or unsuccessful upgrade cannot pass. npm12's inherited npm_config_allow_scripts wrapper option is removed only from child environments; user configuration is unchanged. Mode-preserving materialization also works under a private umask.

## Native completion and evidence

Normal execution keeps the actual SDK parser and uses its public codexPathOverride seam for an owned relay around the published @openai/codex bin. It records prepared executable/prompt/settings, original bounded CLI stdin/stdout/stderr bytes/hashes and JSONL before forwarding to the SDK. Original CLI records and SDK-normalized events are compared; original missing cache-write remains unknown while the pinned SDK may insert0. CLI reports are separate from unknown raw provider measurements/billing.

The relay and validator process runner observe owned descendant PIDs and separate job groups through a bounded host process inventory. Cancellation first freezes the root and observed job groups to capture their descendant closure, then resumes TERM handling and escalates to KILL. Exit confirmation covers the observed tree; parent emergency cleanup handles a stalled relay without signaling its inherited application group. Delayed startup, ignored signals, a same-group grandchild, late output, malformed UTF8/JSON, missing usage, output overflow, startup and recording faults are covered. Native operations/iterator cleanup drain before final receipts. Caller-injected SDK/factory resources have separate ownership labels and bounded cleanup waits; uncooperative caller work cannot report success or confirmed drain. The published CLI is exercised through a controlled loopback Responses provider with a synthetic key/model: a real exec_command upgrades the target through the normal CLI, and cancellation drains its ordinary separate job group and TERM-ignoring grandchild. Supervisor host ancestry authorizes cleanup; model output and namespace PIDs do not. These are offline runtime checks, not paid model judgment.

The actual installed SDK/public executable seam is exercised with a controlled synthetic CLI child. A successful adapter result needs a thread, one active turn, coherent item identities, no pending work, a terminal turn.completed and a nonblank final answer. Tool activity invalidates earlier progress prose. Missing/blank/replayed/unknown/trailing/in-progress output, external tools, malformed/oversized events, failed turns and cancellation cannot pass. Documented nonfatal error items and recoverable connection diagnostics are preserved separately; they cannot establish completion without a coherent terminal turn. These checks validate the returned protocol; the CLI may already have edited the disposable checkout. Failed protocol/recording attempts retain those actual changes.

Original decoded SDK events, unknown fields, errors, usage, task hash and requested model remain in private prepared/failed receipts. SDK-observed missing/invalid/zero counters are separate from unknown provider measurements/cost. SDK0.162.1 inserts absent cache_write_input_tokens=0; it must not be called original provider or raw CLI evidence. A completed upgrade followed by a native failure still fails the overall run while its independent compatibility result and changed files remain visible. Recording faults stop further verification and retain failed/in-memory evidence when possible.

**98 offline checks pass locally**, including actual SDK protocol/upgrade/fresh npm validation, original-head scope, committed/ignored/type/alias/script mutations, source continuity, private modes, caller completion, recording faults and real key-negative CLI. Normal owned CLI proofs cover successful upgrade plus SIGINT/SIGTERM/SIGHUP, including cancellation after real edits. Delayed recording is drained and final failed files remain stable. ## Remaining work and scope

[PLAN.md](PLAN.md) tracks exact Linux/source-distribution qualification and the remaining portfolio. The reproduced ordinary bundled job-group leak is fixed and qualified through the actual pinned SDK/CLI. `--provider-base-url` uses the public SDK option; explicit URLs require HTTPS or loopback HTTP and reject credentials, query and fragment. Default provider behavior is unchanged. Process inventory is bounded (1024 observed members, 4MiB metadata response, one-second inventory deadline/two-second uncertain-exit cap); uncertain inventory/cleanup fails. Reparented observed groups remain owned, while arbitrary malicious detach, unobserved rapid daemonization and PID-namespace/OS containment are outside this application supervisor's guarantees. Defunct process states are recorded separately from runnable processes and group absence. Original CLI stdout is capped at1MiB, stderr64KiB and prompt16KiB; SDK evidence is capped at2000 events/1MiB. These are retained/local operation bounds, with separate cleanup/storage, not hard peak heap, provider retry/traffic/billing or end-to-end wall-clock guarantees.

The changed-file check is an application policy gate, not an OS sandbox for arbitrary malicious code. Use disposable synthetic repositories. The CLI receives workspace-write/network-disabled/web-search-disabled/never-approve settings, but the grader's location outside working context alone is not an enforced read boundary. Source/API protocol and fixture compatibility are qualified independently from live semantic quality and account behavior.

[Scenarios](scenarios/README.md) map twelve versioned cases/four profiles, original install/test expectations and no-edit boundaries. New Firedrill integration requires the qualified release/contract/persisted scenarios. Publication/license choices remain parked; this repository is private.

This full fresh locked extraction gate passes locally; exact Linux CI is required for the pushed source. Gzip metadata is normalized across macOS/Linux.
