# Working rules

Keep the seed and both vendor packages synthetic. Do not let the repair agent modify either vendor directory, tests or unrelated documentation. Validate a dependency change from a separate fresh `npm ci --offline` install; a passing test in an old `node_modules` directory does not prove lockfile consistency.

The grader stays outside the agent checkout. Do not call scripted tests live Codex proof. Add Firedrill integration only against the verified new release.

Keep original baseline commit/tree outside the agent checkout and require it for scope. Never replace it with current HEAD; include ignored/committed/type/alias/mode changes. Materialize only a coherent validated source and reject altered package scripts/metadata before execution. Fresh validation uses offline npm-ci and unchanged public tests/external grader, rechecking source between commands. Do not let SDK completion or prose override failed compatibility/scope.

Decoded SDK events are not raw provider/CLI proof. Keep SDK-inserted cache-write zero distinct from unknown original measurement, preserve failure/partial edits and stop work on recording faults. Runtime config/key/home is owned per call; caller SDK injection remains caller-owned. Initial44 checks only qualify cooperative SDK cleanup. An actual SIGTERM-ignoring child outlives its deadline: process/group supervision/raw CLI capture and async verifier command cleanup remain priority PLAN.md work before stronger bounds. Preserve historical live evidence as historical; do not refresh paid runs without its parked gate.
