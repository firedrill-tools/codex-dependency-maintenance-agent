# Dependency maintenance qualification

## Completed initial guards

Node20+ POSIX local filesystems, pinned @openai/codex-sdk0.162.1 and actual public codexPathOverride/runStreamed API are qualified by controlled executable tests. Those tests use the real SDK parser/process interface with a synthetic child; they do not execute a paid provider or establish the actual bundled CLI's model choices, retry behavior or filesystem sandbox effectiveness.

Original source is captured before any agent in a caller-owned in-memory baseline and private receipt. It binds the original Git commit, root inode/device/mode and complete bounded regular tree hashes/sizes/types/modes. Capturing an arbitrary current HEAD is not a baseline API. Source comparison includes ignored files, committed changes and newline paths, excludes generated root node_modules/.git metadata, rejects unsupported aliases/types and checks original Git objects with external diff/text conversion/hooks/fsmonitor disabled. Source bounds are512 entries,1MiB/file,8MiB total; reads retain at most the statted bound plus one byte and detect changed descriptors/content. This is integrity validation of local cooperative records, not an OS access sandbox or arbitrary-race proof.

Only the three declared files may change, retaining regular types and original modes. Package metadata/scripts must remain original and the dependency must remain the original local v1 or requested local v2; final acceptance requires actual v2 behavior and all three changed files. Protected scripts/tests/extra files cannot reach execution. Candidate bytes are captured once and materialized, preserving modes inside a new0700 directory, without copying symlinks or old installed modules. Fresh npm-ci offline ignores lifecycle scripts, then runs unchanged public tests and an external grader. Original and validation source are rechecked between commands, detecting candidate mutation and self-modifying test imports. Command exit/signal/error/output overflow cannot pass. npm12 wrapper allow-scripts environment is removed without editing user config.

The SDK adapter records each bounded decoded event before interpreting it. Thread/turn order, item identity/type/terminal state, no pending work and nonblank terminal answer are checked; a subsequent command/file event clears earlier progress text. EOF without turn.completed, error/failed turn, unknown/external/replayed/trailing/pending/malformed/oversized events and cooperative timeout/cancellation fail. Edits before failure remain actual source facts; overall failure cannot be erased by a compatible fresh install. One call to runStreamed is made per adapter attempt; provider-internal attempts are not exposed/claimed.

SDK usage is retained in its event and separately classified field-by-field as observed/unknown/invalid. Explicit SDK zero stays zero; no sums/cost are fabricated. Optional native total99 remains99. Missing cache-write may be inserted as0 by this SDK, so its source is always SDK-observed with that caveat, never raw provider or original CLI evidence. Actual model and provider usage/cost remain unknown. Errors retain original SDK name/message/code plus caller/deadline abort reason, with the SDK error retained as a cause when the caller reason is surfaced.

Owned native configuration uses an explicit key, a newly private temporary Codex home and restricted child environment. Its home is removed after iterator cleanup; caller-injected SDK configuration remains caller-owned. Private atomic flushed receipts precede preparation/native work and retain task hash/baseline/events/source/compatibility/error. Sticky recording faults stop subsequent verification; final durable publication is attempted as failed. If storage remains unavailable, the caller gets in-memory failed evidence with unknown last durable status. Reports and disposable source/checkouts are retained for inspection.

44 offline checks include complete actual SDK upgrade/fresh validation, missing terminal/pending/blank/unknown/external/replayed/malformed/oversized/trailing/progress cases, SDK usage source distinctions, failure after real edits, isolated configuration/cooperative cancellation, recording faults, original committed protected edits, allowed commits, ignored/newline/alias/type/mode/script changes, moving source/self-modifying validation, private umask and real key-negative/help/strict CLI.
